# NoviFood — описание проекта

NoviFood — PWA-приложение для персонального учёта питания, воды и веса. Пользователь ведёт дневник приёмов пищи, следит за калориями и Б/Ж/У, хранит собственные продукты и при необходимости получает оценку блюда по фото, голосу или текстовому описанию.

Этот документ описывает реализованную систему. Он заменяет прежний план работ и не является бэклогом.

## Возможности

- Дневник питания по дням: добавление, редактирование и удаление приёмов пищи, выбор типа приёма пищи и фактического веса порции.
- Сводка за день: калории и Б/Ж/У относительно индивидуальных целей, а также серия дней с внесёнными приёмами пищи.
- Ручной ввод, быстрый выбор недавних блюд и множитель порции.
- Распознавание еды на фотографии: изображение сжимается в браузере и передаётся на защищённый серверный API.
- Голосовой сценарий: запись речи, расшифровка, поиск подходящих продуктов и, при необходимости, ИИ-оценка. Перед сохранением можно изменить название, значения на 100 г и вес порции.
- База продуктов: поиск по личным продуктам и кэшу Open Food Facts, создание, редактирование и удаление личных записей. Питательная ценность указывается на 100 г.
- Учёт выпитой воды с дневной целью.
- История дневника, недельная статистика и журнал веса.
- Экспорт и импорт дневника и веса в CSV.
- Регистрация и вход по email/password, изоляция пользовательских данных через Supabase RLS.
- Русский и английский интерфейсы, светлая и тёмная темы, адаптивная навигация и офлайн-страница PWA.

## Пользовательские разделы

| Маршрут | Назначение |
| --- | --- |
| `/` | Дневник выбранного дня: сводка КБЖУ, вода, приёмы пищи, ручной, фото- и голосовой ввод. |
| `/history` | Просмотр дневника по датам и поиск по блюдам. |
| `/products` | Поиск каталожных и личных продуктов, управление личной базой. |
| `/stats` | Недельные показатели калорий и БЖУ, серия дней. |
| `/weight` | Добавление, удаление и просмотр истории веса. |
| `/settings` | Цели по калориям, БЖУ и воде; импорт/экспорт CSV; управление сессией. |
| `/login` | Регистрация и вход по email/password. |

На телефонах используется нижняя панель навигации, на экранах от `md` — боковая панель. Настройки темы и языка хранятся локально в браузере.

## Архитектура

```text
Browser UI
  ├─ React-клиенты страниц и компонентов
  ├─ Supabase browser client → пользовательские данные
  ├─ Next.js API → ИИ и продукты
  │    ├─ Gemini API
  │    └─ Open Food Facts
  └─ Service worker → кэш приложения и offline fallback

Supabase
  ├─ Auth
  └─ Postgres + RLS
       ├─ meals, settings, weight, water_intake
       ├─ user_products
       ├─ products (общий кэш Open Food Facts)
       └─ ai_usage
```

Клиентские компоненты получают данные через модули из `src/lib/`; повторные запросы кэшируются в памяти браузера. `useAuthenticatedQuery` ожидает восстановления сессии до первого защищённого запроса. Для серверных обработчиков используется SSR-клиент Supabase, поэтому ключ Gemini не попадает в браузерный bundle.

## Данные и права доступа

После применения всех миграций используются следующие сущности:

| Таблица | Назначение |
| --- | --- |
| `meals` | Блюда дневника: название, время, тип, калории, БЖУ, заметки и `weight_grams`. |
| `settings` | Одна строка целей на пользователя: калории, БЖУ и вода. Создаётся триггером при регистрации. |
| `weight` | История измерений веса. |
| `water_intake` | Объём и время записей о воде. |
| `ai_usage` | Число успешных ИИ-запросов на пользователя и UTC-день. |
| `products` | Общий кэш продуктов из Open Food Facts; доступен для чтения авторизованным пользователям. |
| `user_products` | Личная база продуктов, включая значения, сохранённые из ИИ. |

Таблицы личных данных привязаны к `auth.users.id`. Для них включён RLS: пользователь видит и изменяет только строки со своим `user_id`. У личных продуктов нормализованное имя уникально в пределах пользователя; это предотвращает дубли при повторных голосовых или ИИ-записях.

## ИИ и каталог продуктов

### Распознавание

`POST /api/analyze-food` принимает сжатое изображение и возвращает название блюда и КБЖУ видимой порции. `POST /api/transcribe-voice` расшифровывает аудио, а `POST /api/analyze-voice` преобразует текстовое описание в название, оценочный вес порции и КБЖУ на 100 г.

Все три маршрута требуют авторизацию. Для успешных запросов действует общий лимит — 50 обращений Gemini на пользователя в UTC-сутки. Вызовы ограничены по времени, а при недоступности или исчерпании квоты одной модели приложение пробует следующую совместимую Flash-модель. `GET /api/check-gemini` — диагностический маршрут для проверки настройки ключа после развёртывания.

### Поиск продуктов

`GET /api/products/search?q=…` сначала ищет по подстроке в личной базе и локальном кэше. Если совпадений нет, сервер запрашивает Open Food Facts, возвращает до 10 результатов и кэширует их в `products`. В памяти процесса есть пяти минутный кэш внешних ответов и ограничение в 10 внешних запросов в минуту на пользователя.

`/api/products/personal` предоставляет CRUD личной базы. Значения БЖУ и калорий не могут быть отрицательными; при указании веса итоговые значения для дневника вычисляются пропорционально граммам.

## API-маршруты

| Метод и маршрут | Описание |
| --- | --- |
| `POST /api/analyze-food` | Анализ фотографии блюда Gemini. |
| `POST /api/transcribe-voice` | Расшифровка аудиозаписи Gemini. |
| `POST /api/analyze-voice` | Оценка продукта и порции из текста. |
| `GET /api/check-gemini` | Безопасная диагностика конфигурации Gemini. |
| `GET /api/products/search` | Поиск локальных и внешних продуктов. |
| `GET/POST/DELETE /api/products/personal` | Чтение, сохранение и удаление личных продуктов. |
| `GET /auth/callback` | Завершение аутентификационного сценария Supabase. |

## Конфигурация и запуск

Создайте `.env.local` в корне проекта:

```env
NEXT_PUBLIC_SUPABASE_URL=https://<project-id>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon-key>
GEMINI_API_KEY=<Google-AI-Studio-key>
```

`GEMINI_API_KEY` используется только на сервере и не должен иметь префикс `NEXT_PUBLIC_`. Опционально `OPEN_FOOD_FACTS_USER_AGENT` задаёт User-Agent для внешнего каталога.

Установите зависимости и примените все миграции:

```bash
npm install
npx supabase db push
npm run dev
```

Перед `dev` и `build` скрипт генерирует `public/sw.js`. Для production-сборки используйте `npm run build`, для локального запуска собранного приложения — `npm start`.

## Проверки качества

```bash
npm run lint       # ESLint для Next.js и TypeScript
npm test           # Vitest: утилиты, API и React-компоненты
npm run test:e2e   # Playwright в Chromium
```

Модульные тесты покрывают расчёты порций и серий, CSV, доступ к микрофону, интеграцию Gemini, API продуктов и ИИ, а также ключевые компоненты. E2E-тесты проверяют навигацию и основной сценарий дневника.

## Развёртывание и эксплуатация

Приложение рассчитано на развёртывание в Vercel или другой среде, поддерживающей Next.js server routes. В окружение развёртывания нужно добавить те же три обязательные переменные и применить миграции к связанному проекту Supabase. После первого развёртывания откройте `/api/check-gemini`, чтобы убедиться, что Gemini-ключ доступен и действителен.

Service worker кэширует приложение и страницу offline. Новый build получает новый идентификатор кэша; при появлении обновления интерфейс предлагает применить его.
